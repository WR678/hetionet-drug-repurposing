# Reproducibility audit

Paper: Himmelstein DS, Lizee A, Hessler C, Brueggeman L, Chen SL, Hadley D, Green A, Khankhanian P, Baranzini SE (2017). Systematic integration of biomedical knowledge prioritizes drugs for repurposing. *eLife* 6:e26726. <https://doi.org/10.7554/eLife.26726>
Audited by: Rui Wang on 2026-10-26

| Row | Score (missing / decent / good / great) | Evidence (links, quotes) |
|-----|------------------------------------------|--------------------------|
| Data | great | Hetionet v1.0 is public on GitHub (<https://github.com/hetio/hetionet>, tag `v1.0.0`) and Zenodo (<https://doi.org/10.5281/zenodo.268568>) in JSON, TSV and Neo4j formats; other project deposits are on figshare (<https://doi.org/10.6084/m9.figshare.c.2861359.v1>). The network is built from its sources by notebooks in <https://github.com/dhimmel/integrate>, whose README says "All GitHub links use commit hashes to be version specific". A public Neo4j browser is at <https://neo4j.het.io>. |
| Code | good | All code is public on GitHub with tagged releases archived on Zenodo (`dhimmel/integrate` v1.0 and v2.0, `dhimmel/learn` v1.0.0, `hetio/hetnetpy` up to v0.3.1); eLife keeps copies at <https://github.com/elifesciences-publications>. The `learn` README lists the order in which to run the notebooks, but warns that "it may not be possible to rerun all notebooks sequentially". Random seeds were not checked. |
| Environment | good | `dhimmel/integrate/environment.yml` pins every conda package with its build (`python=3.5.1`, `pandas=0.17.1`, `py2neo==2.0.8`), for Linux only. `dhimmel/learn` has no environment file of its own: its README says it uses "approximately the conda environment" of `integrate`. No container. Whether these 2016 packages can still be installed was not tested. |
| FAIR | great | Persistent identifiers for the paper, the data (Zenodo, figshare) and the code (Zenodo). The Thinklab discussions cited in the paper (e.g. <https://doi.org/10.15363/thinklab.4>) still resolved on 2026-10-26, to the static archive at <https://think-lab.github.io>, although Thinklab closed in 2017. Open formats (TSV, JSON); the JSON release carries source and license properties on each node and edge; node and edge types are described in `describe/` of the hetionet repository. |
| License | good | The article is CC BY 4.0. The READMEs of `hetionet`, `integrate` and `learn` release all original content, data and code, as CC0; the licenses of the integrated resources are attached to each node and edge. The section "Data copyright and licensing" reports that 9 of the 31 resources considered had no license at all. There is no LICENSE file in these repositories (GitHub shows no license), and CC0 is not a usual software license; `hetio/hetnetpy` has a BSD license file. |
| Documentation | good | Each repository has a README with an execution order (`integrate`: `precompile.sh`, then `build.sh`); the manuscript is rebuilt from source by Manubot (<https://github.com/dhimmel/rephetio-manuscript>); the whole project was run as an open lab notebook on Thinklab. There is no single command or workflow that reruns the predictions. |

The one change that would help most: give `dhimmel/learn` its own rebuildable environment (a lock file or a container) and one driver script that reruns the predictions from Hetionet v1.0, so that a reader can recompute the model performance without reconstructing a 2016 environment by hand.

Could I reproduce one number? How long did it take, and what stopped me? Yes, for the size of the network. From `hetionet-v1.0-nodes.tsv` and `hetionet-v1.0-edges.sif.gz` in the hetionet repository (CC0; SHA-256 `3ad9eb86c031df8bc7d5efefa6edc93562182eb9a6a71e5129d3f18b9d42c50e` and `611f0411ac666be4e0270e54bbca67407e14720bfc3099311f0f5eec25c5a947`, downloaded 2026-10-26), I counted 47,031 nodes, 2,250,197 edges and 755 Compound–treats–Disease edges, exactly as in the paper, in about 5 seconds (two downloads and three shell commands). I did not try to reproduce the model performance (AUROC): that needs the 2016 Python 3.5 environment, a Neo4j database and the DWPC feature extraction, and the `learn` README warns that the notebooks may not rerun in order.
