# Hetionet drug repurposing

Lightweight, CPU-only drug repurposing on the Hetionet knowledge graph with a small R-GCN and a simple baseline

Author: Rui Wang ([ORCID 0009-0008-5273-0060](https://orcid.org/0009-0008-5273-0060))

## Proposal

Can a small relational graph neural network (R-GCN), trained on a laptop CPU in
a few minutes, rank known drug–disease treatment links in a public biomedical
knowledge graph better than a simple neighbourhood baseline? This is a small,
fully reproducible version of the graph-based drug repurposing question in my
own research. The data is Hetionet v1.0 (Himmelstein et al. 2017, *eLife*,
<https://doi.org/10.7554/eLife.26726>; archived on Zenodo,
<https://doi.org/10.5281/zenodo.268568>): 47,031 nodes of 11 types and
2,250,197 edges of 24 types, with a 12.4 MB edge list
(`hetionet-v1.0-edges.sif.gz`). Original Hetionet content is CC0; the source
databases it integrates keep their own licenses, which will be listed in
`metadata/`. I will use the compound–gene, disease–gene, compound–compound and
disease–disease edges, and predict the 755 compound–treats–disease edges. I
expect to produce a held-out evaluation (AUROC and average precision, mean ±
SD over three random seeds) of a two-layer R-GCN against a common-neighbour
baseline, a table of top-ranked candidate drug–disease pairs, and a Quarto
report, all rebuilt by `pixi run reproduce`, with a target of under 15 minutes
on a laptop CPU.

## Reproduce the results

You need [Pixi](https://pixi.prefix.dev/latest/) and an internet connection.
Then, from this folder:

```bash
pixi install          # builds the exact environment recorded in pixi.lock
pixi run reproduce    # downloads the raw data and rebuilds every result
```

`pixi run reproduce` must work on a fresh clone of this repository. A GitHub
Action (`.github/workflows/reproduce.yml`) checks that on every push.

## What is where

| Folder | What goes in it | Rule |
|--------|-----------------|------|
| `data/raw/` | Data exactly as you received it | Read-only. Never edit; download it with a script. Not committed. |
| `data/processed/` | Data derived from raw data | Regenerated by code. Not committed. |
| `metadata/` | Sample sheet, data sources, checksums, data dictionary | Small text files, committed. |
| `scripts/` | Code you write (Python, shell) | Committed. |
| `config/` | Parameters for the analysis or workflow | Committed. |
| `workflow/` | Snakemake and Nextflow pipelines | Committed. |
| `notebooks/` | Jupyter notebooks for exploration | Committed, outputs cleared or small. |
| `reports/` | Quarto documents that turn results into a report | Source committed, rendered HTML not. |
| `results/` | Figures, tables, logs made by the code | Regenerated. Not committed. |
| `docs/` | Longer documentation | Committed. |
| `envs/` | Conda `environment.yml` exports, for people without Pixi | Generated from `pixi.toml`. |
| `containers/` | Dockerfile and Apptainer recipe | Committed. |

Each folder has its own `README.md` with more detail.

## Data

Hetionet v1.0, edge list `hetionet-v1.0-edges.sif.gz` (12.4 MB), from
<https://github.com/hetio/hetionet> (archived on Zenodo,
<https://doi.org/10.5281/zenodo.268568>). Original Hetionet content is CC0;
integrated sources keep their own licenses. The download script, sources and
checksums will be added in `metadata/` (lesson 03).
